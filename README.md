# PHANTOM SHIELD — Intelligent Email Threat Analysis

**Spam / Phishing Email Detector Using NFA and DFA** (Theory of Computation project)

A local web application. A character-level **ε-NFA** recognises five keyword categories, **subset
construction** converts it into a **DFA**, and both simulators report identical match positions.
Everything is generated by the real Python code: nothing in the interface is a static picture.

> Educational keyword-based detector. **SAFE does not prove an email is legitimate**, and the tool
> cannot detect every phishing attempt.

## 1. Problem statement and objectives
Detect suspicious wording in an email using finite automata, show how an NFA becomes a DFA, and
compare the two simulators on the same inputs.

* Build a real ε-NFA for literal patterns; convert it with the subset-construction algorithm.
* Report **every occurrence** (start, end, original text) using automata state information.
* Visualise both automata, the construction steps, and the DFA transition table.
* Measure NFA versus DFA runtime honestly.

## 2. Features
Overview dashboard · Email Scanner (paste, `.txt`, `.eml`, samples) · Live demonstration mode ·
NFA Explorer · DFA Explorer · Subset Construction stepper · DFA Transition Table (search, filter,
copy, CSV, JSON) · Performance Lab (Matplotlib charts) · 20-email Dataset · About page.

## 3. Install and run (Windows, VS Code)
Requirement: Python 3.10+ from python.org (tick **Add Python to PATH**).

**Easiest:** extract the ZIP, then double-click `run_windows.bat`. It creates `.venv`, installs the
requirements and starts the server. Open <http://127.0.0.1:5000> in your browser.

**Manual (VS Code terminal, inside the `phantom_shield` folder):**
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```
Then open http://127.0.0.1:5000. The server listens on `127.0.0.1` only (set `PHANTOM_HOST` to change).
No internet is needed after installing the packages: all CSS, JS and icons are local.

**Run the tests:** double-click `run_tests.bat`, or `python -m pytest -v`.

**Print the automata for your written report:** `python export_automata.py`

## 4. Using the scanner
1. Open **Email Scanner**, paste any email (or press *Load Example*), choose the threshold.
2. *Analyze Email* runs both automata; *Run NFA* / *Run DFA* run one; *Compare Both* opens the comparison tab.
3. Results show verdict, score /5, categories, every occurrence with positions, timings and an explanation.
4. *Show Matching States* / *Step Through Automaton* open the real NFA/DFA trace for the current text.
5. Editing the text immediately clears old results, so stale results are never shown.

**Uploads.** `.txt` (UTF-8, UTF-16 with BOM or Windows-1252) and `.eml` (multipart, encoded headers,
HTML-only bodies converted to text). Limit 1 MB. Several emails in one `.txt` are separated by a line
containing exactly `---EMAIL---` (see `data/sample_email.txt`). The parsed list lets you load or scan
each email, or scan all. Attachments are never opened and no link is ever fetched.

## 5. Theory
### Patterns and alphabet
| Category | Literal(s) |
|---|---|
| FREE | `free` |
| WIN_WON | `win`, `won` (two branches, **one** category) |
| CLICK_HERE | `click here` |
| URGENT | `urgent` |
| VERIFY_ACCOUNT | `verify your account` |

Σ = the 18 distinct characters used by the literals (including the space) plus the symbolic class
**OTHER** (every character not in the set). OTHER is a class, not a literal character.
Matching is case-insensitive literal substring matching (no word boundaries, so `window` matches `win`).
Normalisation is done character by character (`c.lower()` if it is one character inside the
alphabet, otherwise OTHER), so indices in the normalised text equal indices in the original text.
Positions are zero-based; the end is exclusive.

### The NFA  N = (Q, Σ, δ, q0, F)
* **Q**: q0 plus L+1 states per literal of length L (52 states with these patterns).
* **δ**: q0 loops on every symbol of Σ; six **ε-transitions** go from q0 to the first state of each
  branch; inside a branch each state moves on the next literal character.
* **q0**: the initial state. **F**: the last state of each branch, labelled with its category and length.
The self-loop plus ε-moves let a pattern start at any position of the email.

### Subset construction
`automata/subset_construction.py` computes ε-closure(q0) as D0, then for every unprocessed subset and
every symbol computes `move` and the ε-closure, reusing known subsets and creating new DFA states
for unseen ones. A DFA state is accepting if its subset contains an accepting NFA state. The empty
subset would be a dead state, but it is **unreachable** because q0 loops on every symbol, so the DFA
has no dead state. The result here: 45 DFA states, 6 accepting, 19 × 45 = 855 transitions
(the *Subset Construction* page shows all 856 calculation steps; the first is the start closure).

### Occurrence tracking
Each accepting NFA state stores its category and literal length. After consuming character `i`, every
accepting state in the active set (NFA) or in the current DFA subset (DFA) reports a match
`[i+1-length, i+1)`. No regular-expression engine is involved. Both simulators therefore return
identical intervals, even for adjacent or overlapping matches (`winwon`, `freefree`).

### Scoring (application rule, not automata theory)
Score = number of **distinct** categories matched (0–5). Verdict = `SPAM DETECTED` if score ≥ threshold
(default 2, configurable 1–5), else `SAFE`. Repeated occurrences are listed but score once.

## 6. Performance methodology
`services/benchmark.py` checks that NFA and DFA outputs are equal, runs warm-up passes, then times
repeated passes over the whole dataset with `time.perf_counter()` and reports median, mean, min, max and
per-email values. Charts are drawn by Matplotlib from those measurements and saved in `generated/`.
The DFA does one table lookup per character, the NFA manipulates a set of states, so the DFA is
usually faster in Python; the DFA needs more states and memory. If a run shows something else the page
reports it as measured. Results depend on your computer.

## 8. Lecturer demonstration workflow
1. Overview: point out the live counters (they start at zero).
2. Email Scanner → press **Demonstration mode** (larger text, sidebar hidden).
3. Let the lecturer paste or upload any email → **Compare Both** → read verdict, highlights, positions.
4. **Show Matching States** → step through the NFA with *Next Step*; note the ε-closure column.
5. NFA Explorer → DFA Explorer → **Subset Construction** (Next new state) → **DFA Transition Table**.
6. **Performance Lab** → Run Benchmark and discuss the measured values and the state counts.

## 9. Limitations
* Literal substring matching only (no word boundaries, synonyms, misspellings, images or URL analysis).
* Large emails: scans are fast, but step traces are limited to 400 characters (a window around the first match is used).
* Benchmarks measure Python simulators, not optimised native code.
* Keyword detection is educational and not a substitute for professional email security.

## 10. Privacy
Email text is processed locally, never sent anywhere, never written to disk and never logged.
Session statistics keep only counts, length and verdict.
