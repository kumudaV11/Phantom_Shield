How NFA and DFA work

An NFA can be in several states at once. Our NFA keeps a start state that loops on every character and uses ε-transitions to begin every pattern at any position.

Subset construction turns it into a DFA: each DFA state is a set of NFA states, and every character causes exactly one transition.

    Algorithm

    1. Compute the ε-closure of the NFA start state; it becomes the DFA start state D0.
    2. Take each unprocessed DFA state (a subset of NFA states).
    3. For every symbolic input class compute move, then its ε-closure.
    4. If that subset is already known reuse its DFA state; otherwise create a new one.
    5. A DFA state is accepting if its subset contains an accepting NFA state.
    6. Repeat until no unprocessed subsets remain.

      About Project

      Spam / Phishing Email Detector Using NFA and DFA

      PHANTOM SHIELD is a Theory of Computation project. A character-level ε-NFA recognises five keyword categories; subset construction produces the equivalent DFA; both simulators report the same occurrences.

      Pattern categories

        Scoring rule (application-specific)

        The spam score is the number of distinct categories matched (out of five). The verdict is SPAM DETECTED when the score reaches the threshold (default 2), otherwise SAFE. This rule is not part of automata theory.

        Limitations

        • Literal substring matching: window contains win, so it matches.
        • Keyword-only: misspellings, images and unusual wording are not detected.
        • SAFE does not prove that an email is legitimate. This is an educational tool, not enterprise email security.

        Privacy

        Email text is processed locally, never sent to external services, never written to disk, and only counts (not text) are kept in session statistics.
